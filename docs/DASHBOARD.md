# Обзор бизнеса

Web: `/dashboard`. Источник показателей — `GET /finance/summary?from=YYYY-MM-DD&to=YYYY-MM-DD&storeId=...`. API требует `finance.view`, ограничивает выбранный магазин правами сотрудника и возвращает суммы в минимальных единицах валюты.

Экран показывает выручку за вычетом возвратов, валовую прибыль, расходы, операционный результат, число оформленных чеков, средний чек по продажам до возвратов, сумму скидок, число и сумму возвратов. Периоды: сегодня, 7 и 30 дней. Список магазинов берётся из `GET /finance/stores`; сотрудник видит только доступные ему магазины. По умолчанию список и три отчёта используют `scope=active`: только действующие магазины. Переключатель «Включить архивные магазины» передаёт `scope=all`, включает их исторические операции в общую сводку и позволяет выбрать архивную точку отдельно. Панель текущих остатков в режиме архива скрыта.

График «Продажи по дням» получает данные из `GET /finance/sales-trend` с теми же `from`, `to`, `storeId`. API агрегирует продажи и возвраты по UTC, заполняет дни без операций нулями и показывает чистую выручку каждого дня. Оранжевый столбец обозначает день, в который сумма возвратов превысила продажи. Доступ требует `finance.view` и учитывает назначенные сотруднику магазины.

Рейтинг «Топ товаров» получает данные из `GET /finance/top-products` с теми же фильтрами. API складывает количество и сумму позиций завершённых продаж, вычитает возвращённые позиции по дате возврата и показывает пять товаров с наибольшим положительным количеством после возвратов. Рядом отображается выручка по этим позициям после возвратов. Для исторической аналитики товар остаётся в рейтинге, даже если затем был архивирован. Доступ требует `finance.view` и ограничен назначенными магазинами.

Долг клиентов хранится как общий баланс в карточке клиента, поэтому при выборе отдельного магазина он показан как недоступный. Общий долг клиентов не разделяется по действующим и архивным магазинам. Пустой период возвращает ноль чеков и нулевой средний чек.

Проверка на тестовой PostgreSQL и в браузере: `node tools/verify-dashboard.mjs` при работающих API и Web. Нужны `DATABASE_URL`, `KOREACRM_TEST_LOGIN`, `KOREACRM_TEST_PASSWORD`; для проверки мобильного экрана через Edge CDP на порту 9226 добавьте `KOREACRM_TEST_BROWSER=1`. Скрипт сравнивает общую сводку в обоих режимах с данными базы.
