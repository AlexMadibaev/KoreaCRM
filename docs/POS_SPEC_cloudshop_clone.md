# KoreaCRM POS — ТЗ кассы 1 в 1 по CloudShop (wpapp 4.0.1)

Источник: живой разбор web.cloudshop.ru/wpapp (новая версия) + /pos (старая) на тестовом аккаунте, 02.11.2026.
Цель: экран кассы KoreaCRM повторяет CloudShop по раскладке, цветам, шрифтам, размерам и логике.
Не копируем: логотип/название CloudShop, их иконки-ассеты (берём аналогичные из Material Symbols / lucide).
Не копируем баги — раздел 9 «Отличия от оригинала» (исправленная логика).

## 2. Раскладка главного экрана (эталон 1144×847)

```

│[▦56]│ Поиск по наименованию, артикулу, штрихкоду… (610×60) │[F]│▌│ 🔍 Розничный покупатель  [C] │[+👤]│  h=64

│ сетка карточек 161×329, gap 4, padding 4                       │▌│ Рекомендации            [⚙]  │  h=34
│                                                                │▌│ строки чека / «Выберите      │
│                                                                │▌│ товары» (по центру)          │
│                                                                │▌│ Подытог / Скидка             │
```

- Левая колонка ≈59%, правая ≈40% (458px), между ними разделитель 10px `--pos-border`, перетаскиваемый (resize).
- Топбар левой части: кнопка режима каталога 56×56 (`--pos-primary-2`, r4, иконка «плитки») → поле поиска (bg surface, без рамки) → kbd «F».
- Топбар правой части: иконка поиска, имя клиента 20/500, kbd «C», кнопка 56×55 `--pos-accent` с иконкой «добавить человека».
- Нижняя панель левая (surface): «☰ Меню» | «{Магазин} / Смена #{N}» по центру | «2 ноября, понедельник 03:23» + индикатор сети (зелёный / красный при офлайне).
- Нижняя панель правая: кнопка на всю ширину `--pos-primary`, слева «⋮», «ПРОДАЖА», справа сумма. Неактивна (тусклая) при пустом чеке. В режиме возврата — жёлтая «ВОЗВРАТ ПРОДАЖИ».

### Карточка товара (сетка)
- 161×329 (размер настраивается 150–350), bg surface, при наведении/фокусе рамка 1px `--pos-accent`.
- Сверху остаток «N шт» (text-3, по центру).
- Фото 145×132, bg surface-hover, r8; без фото — серая иконка-заглушка.
- Название 16px по центру, до 3 строк, ellipsis.
- Низ: разделитель border, цена 16/600. Если товар уже в чеке — вместо цены степпер «− N +».
- Вид «Список» — строка: фото слева, название, остаток, цена.

### Состояние «смена закрыта»
Правая панель: большая иконка замка (белая) + кнопка «ОТКРЫТЬ СМЕНУ» (`--pos-primary`, r4). Каталог виден, но клик по товару ничего не добавляет.

## 3. Чек (правая панель)

Строка чека (h≈52, border-bottom):
- иконка/фото 32×32 · название (16) + под ним «Цена: 150,00 смн.» (12, text-3) и бейдж «10% скидка» (оранжевый фон, 11px) если есть скидка
- справа: «×2», сумма строки, при скидке — старая сумма зачёркнутая под ней
- крестик «×» удалить строку
- клик по строке → модалка редактирования строки (как «Товар по свободной цене»: цена [если свободная], скидка %/сумма, количество ±, итог, ПРИМЕНИТЬ)

Под строками: блок «Покупают вместе» (рекомендации по истории чеков) с шестерёнкой.

Низ чека:
- «Подытог ……… 300,00 смн.»
- «Скидка 10,00% ……… 30,00 смн.» — сумма синим, кликабельна → поповер «Размер скидки»: переключатель [% | смн.] (активный — оранжевый), поле, кнопка ГОТОВО. Скидка на чек распределяется по строкам пропорционально.
- [ОЧЕРЕДЬ ЧЕКОВ: N] (оранжевая) [НЕПРОВЕДЁННЫЕ: N] (серая) — показываются только если N>0 или чек пуст.

Меню «⋮» (bottom sheet над кнопкой ПРОДАЖА):
- строка продавца: аватар + имя + справа «Продавец» → модалка выбора продавца (поиск)
- «Отложить чек» (иконка history)
- «Отменить чек» (красным)
- «Отмена» [Esc]

## 4. Модалки

Общий стиль: bg surface, r4, ширина 444, заголовок 20/600, справа «ЗАКРЫТЬ [ESC]», кнопка-действие на всю ширину внизу (оранжевая или синяя) с kbd «ENTER». Оверлей rgba(0,0,0,.5).

### 4.1 Товар по свободной цене / редактирование строки
Иконка + название · «Цена» (поле + «смн.», подпись «товар по свободной цене») · «Скидка» два поля [ % ] [ смн. ] (связаны) · «Количество» степпер (pill, кнопки − + 60×60 круглые, число по центру 40px) · «Итог» крупно · ПРИМЕНИТЬ [ENTER].

### 4.2 Создание клиента
Имя покупателя* · Телефон (+ «ДОБАВИТЬ НОМЕР ТЕЛЕФОНА», несколько) · Email · радио [Скидка | Бонусы] · блок «Скидка»: выбор из предустановленных (если пусто — жёлтое предупреждение «Список предустановленных скидок пуст. Администратор может установить их в настройках компании.»), чекбокс «Учитывать накопительные скидки» · Дисконтная карта (иконка карты, можно сканером) · Дата рождения (DD.MM.YYYY) · СОЗДАТЬ [ENTER]. После создания клиент сразу ставится в чек.

### 4.3 Очередь чеков
Список карточек: «Продажа», клиент, время, позиции (название, кол-во, сумма) · кнопки [ВЫБРАТЬ] (синяя) [УДАЛИТЬ] (красный текст).

## 5. Экран оплаты (полноэкранный, bg `--pos-bg`)

Справа сверху «ЗАКРЫТЬ [ESC]». Две колонки по центру:

**Левая «Платежи»** (таблица):
- «> Итог» (раскрывается: Подытог, Скидка, Итог)
- Наличные / Безналичные / Отсрочка — суммы; у внесённых платежей слева красная кнопка «−» (удалить платёж)
- «^ Принято» жирным
- textarea «Комментарий к продаже»
- переключатель «Печатать чек»

**Правая «Принять оплату»**:
- карточка клиента (аватар-инициалы, имя, кнопка ИЗМЕНИТЬ)
- три плитки способа: Наличные / Безналичные / Отсрочка (выбранная — заливка `--pos-primary`)
- поле «Сумма» (по умолчанию = остаток к оплате)
- Наличные: «Варианты оплаты наличными» — кнопки [остаток][200][500][1 000][2 000][5 000][10 000] (первая = точная сумма, далее ближайшие купюры выше)
- Безналичные: кнопка «БАНКОВСКИЙ СЧЁТ» (без интеграции) → модалка «Примите оплату через терминал»: сумма крупно, иконка терминала, кнопка УСПЕШНО [ENTER]
- Отсрочка: только если выбран клиент; блок «Общий долг составит: X» и кнопка ПРИНЯТЬ (оранжевая)
- основная кнопка «ПРИНЯТЬ X СМН.» [ENTER]

Логика:
- Каждое «Принять» добавляет частичный платёж; пока Принято < Итог — остаёмся на экране, поле суммы = остаток.
- Когда Принято ≥ Итог — создаём продажу («Создание продажи… ЗАГРУЗКА») → экран успеха.

**Экран «Продажа прошла успешно»**: Итог (раскрывается), Наличные, Безналичные/«Банковский счёт», Отсрочка, Принято · «СДАЧА:» крупно · кнопка ЗАКРЫТЬ [ENTER].

## 6. Меню (☰)

Поповер над кнопкой «Меню», ширина ~250:
1. Профиль: аватар, имя, роль («Владелец»)
2. Выйти
3. (у них «Вернуться к старой версии» — нам не нужно)
4. — разделитель —
5. Создать возврат (только при открытой смене)
6. Закрыть смену (красным, только при открытой смене)
7. — разделитель —
8. Возврат долга
9. Журнал чеков
10. Смены
11. Настройки

### 6.1 Журнал чеков (модалка ~900 шир.)
Слева фильтр: [ВЫБЕРИТЕ ДАТУ], «Номер документа» (#), «Клиенты» (select-поиск), «Товары» (select-поиск). Сверху «Фильтр» и выбранная дата.
Справа карточки чеков: «Продажа #N» + [ПЕЧАТЬ] [ВОЗВРАТ] + сумма справа · дата, кассир · магазин, клиент · раскрывашка статуса оплаты («✓ Оплачен» или «⚠ Долг X» красным → таблица платежей: иконка способа, Номер, Клиент, Дата, Сумма) · раскрывашка «Список товаров N поз.». Внизу «ЗАГРУЗИТЬ ЕЩЁ».

### 6.2 Возврат по чеку (модалка)
«Возврат продажи» · «ПРОДАЖА #N от дата» · поля выплаты [Наличные] [Банковская карта] (автозаполняются способом исходной оплаты, редактируемые) · поиск товара · таблица Наименование (+ «Доступно для возврата: N») / Цена / Количество (степпер 0..доступно) / Сумма · «Печатать чек» · СОЗДАТЬ ВОЗВРАТ НА СУММУ X [ENTER]. → (если карта) окно терминала → «Возврат успешно создан» (способ, сумма, Итог).

### 6.3 Возврат без чека
Пункт меню «Создать возврат» переводит чек в режим возврата: кнопка снизу жёлтая «ВОЗВРАТ ПРОДАЖИ», пункт меню меняется на «Вернуться к продаже». Оплата — тот же экран, но «Выдать».

### 6.4 Возврат долга
«Список должников» (поиск, «Найдено N», строка: аватар-инициалы, имя, сумма долга) → карточка клиента (шапка цветная, аватар, имя, «Долг X» оранжевым, список продаж с долгом: «Продажа #N, дата, сумма, К оплате») → окно погашения: [Наличные][Банковская карта], «К оплате» (по умолчанию весь долг по чеку), «Общий долг составит: X», ЗАКРЫТЬ ДОЛГ НА СУММУ X [ENTER].

### 6.5 Смены
Слева список смен (фильтр периода «1 января → 2 ноября», группировка по дням, «Смена #N, длительность / открыта в HH:MM, +приход зелёным, −возвраты красным», ЗАГРУЗИТЬ ЕЩЁ).
Справа карточка: «Смена #N», кассир, период · кнопки [Финансовые операции ▾] [Печать] [Закрыть смену] · магазин, касса, кассир, ОС, IP ·
блоки: **Продажи** (кол-во, сумма, наличные, безналичные) · **Возвраты** (кол-во, сумма, наличные, безналичные) · **Касса** (на начало, всех взносов, всех выносов, на текущий момент) · «Выручка с учётом возвратов» · вкладки [ДВИЖЕНИЕ ТОВАРА] [ДВИЖЕНИЕ ДЕНЕГ] — лента чеков (тип+№, ПЕЧАТЬ, время, кассир, магазин, клиент, сумма, статус, «Список товаров N поз.»).

«Финансовые операции» (новая версия: блок с тремя оранжевыми текстовыми кнопками с иконками ↑ ВЫДАЧА, ↓ ПРИЁМ, ⟳ ПЕРЕВОД; «ЗАКРЫТЬ СМЕНУ» — красная кнопка под заголовком, «ПЕЧАТЬ» оранжевая справа).
- Выдача/Приём (модалка): Сумма*, Контрагент* (select), Категория платежа* (select), Комментарий, СОЗДАТЬ [ENTER] (неактивна, пока не заполнены обязательные).
- Закрытие смены: bottom sheet «Вы действительно хотите закрыть смену?» → «Закрыть смену» (красным, Enter) / «Отмена» (Esc).
- Строка «Движение денег»: «Приход #N», сумма, дата, способ (Наличные/Безналичные), счёт (Касса №1 / Банковский счёт), клиент.
- Перевод: Сумма, Счёт (select), Комментарий, ОТПРАВИТЬ.

### 6.6 Открытие смены
Модалка «Открытие смены» · «Сверка денег в кассе» · Касса (select) · «Сумма денег в кассе» (предзаполнено расчётной) · если ≠ расчётной: серый блок «Расчётная сумма в кассе: X · Расхождение по кассе: ±Y · Будет создан расходный/приходный ордер на сумму Y», поле «Комментарий» обязательное (красная подсветка) · ОТКРЫТЬ СМЕНУ.

### 6.7 Настройки кассы (полноэкранно, вкладки слева)
- **Основные**: Оформление (Авто/Светлое/Тёмное), Звук (вкл/выкл), Язык интерфейса, Печать («Печатать чек по умолчанию», Принтер А4 / Принтер чеков, Ширина ленты мм, Размер шрифта мм, Отступ по краям мм), Товары с нулевым остатком (Показывать/Не показывать), Сортировка (Наименование/Цена/Дата изменения + по возрастанию/убыванию), «УСТАНОВИТЬ НАСТРОЙКИ ПО УМОЛЧАНИЮ», «Версия: x.y.z».
- **Оборудование**: безналичные интеграции (статус «Требуется настройка», СОЗДАТЬ ИНТЕГРАЦИЮ), Диагностика: сканер («Отсканируйте код для проверки», Штрих-код:, Маркировка:), весы («Положите товар на весы»).
- **Категории**: «Показывать товары из скрытых категорий» Да/Нет, список категорий с порядком (drag).
- **Отображение товаров**: Группировка модификаций Да/Нет, Сетка/Список, чекбоксы карточки (остаток, изображение, код, артикул, штрих-код), Размер карточки 150–350, Размер шрифта 0.8–1.2, живой «Пример товара».

### 6.8 Режимы каталога (кнопка ▦ слева сверху)
Поповер из трёх плиток 66×66: [Товары] (активная оранжевая) [Категории] [Группы].

## 7. Горячие клавиши
- `F` — фокус в поиск товара (сканер штрихкода пишет туда же; Enter по коду → добавить)
- `C` — поиск клиента
- `Enter` — подтвердить текущую модалку / Принять / ПРОДАЖА
- `Esc` — закрыть модалку / экран оплаты
- `+` / `-` — количество последней строки (у них нет — добавить)

## 8. Модель данных / состояния (минимум)

```
Shift { id, number, register_id, store_id, cashier_id, opened_at, closed_at,
        opening_cash_expected, opening_cash_counted, opening_diff_comment,
        status: open|closed }
Receipt { id, number, type: sale|return, shift_id, customer_id?, seller_id?,
          status: draft|parked|posted|cancelled, comment, discount_pct, discount_sum,
          subtotal, total, paid_total, debt_total, base_receipt_id? (для возврата) }
ReceiptLine { receipt_id, product_id, name, price, qty, discount_pct, discount_sum, total,
              returned_qty }
Payment { receipt_id?, shift_id, method: cash|card|debt, amount, kind: sale|refund|debt_repayment,
          rrn?, card_last4?, created_at }
CashOperation { shift_id, type: in|out|transfer, amount, counterparty_id?, category_id?,
                account_id?, comment }
```

Очередь офлайна: чеки, созданные без сети, пишутся локально (IndexedDB) со статусом `pending` → счётчик «НЕПРОВЕДЁННЫЕ» → фоновая синхронизация.

## 9. Отличия от оригинала (их баги — у нас исправлено)

1. **Сдача** = Наличные принято − (Итог − безнал − отсрочка), только если > 0. У CloudShop при 100 нал + 170 в долг показывает «Сдача 170».
2. После **частичного погашения долга** не показывать «Оплачен», а «Принято X, остаток долга Y».
3. Окно терминала при возврате: «Верните оплату на карту», а не «Примите оплату».
4. **Отчёт смены**: «Сумма продаж» = сумма чеков (начислено); отдельно «Получено» по способам, «Выдано в долг», «Погашено долгов». У них погашение долга смешано с продажами.
5. **Журнал**: статус возврата у чека («Возвращён частично / полностью»).
6. **Закрытие смены**: пересчёт наличных и расхождение в этой же смене + Z-отчёт/печать.
7. **Возврат без чека**: обязательная причина + право доступа.
8. **Карта без интеграции**: необязательные поля RRN / последние 4 цифры.
9. Сдача при смешанной оплате: 100 нал + 170 карта на чек 270 → у них «Сдача 170». Сдача считается только с наличных.
10. Окно возврата: в колонке «Цена» показывают цену без скидки (150), а сумму — со скидкой (135). Показывать цену со скидкой.
11. Чек возврата в журнале: у них перепутаны подписи — у иконки магазина стоит клиент, у иконки клиента стоит магазин.
12. Язык таджикский + валюта TJS + часовой пояс Душанбе по умолчанию.

## 10. Приёмочные сценарии (прогнать на нашей кассе)

1. Открыть смену с расхождением −10 → без комментария нельзя, с комментарием создан расходный ордер 10.
2. Товар по свободной цене 150 × 2, скидка на чек 10% → строка 270 (зачёркнуто 300, бейдж 10%), Подытог 300, Скидка 30, ПРОДАЖА 270.
3. Оплата: 100 наличными → остаток 170 → Отсрочка на клиента → «Общий долг составит 170» → успех, сдача 0.
4. Отложить чек 75 → «ОЧЕРЕДЬ ЧЕКОВ: 1» → Выбрать → оплатить картой → окно терминала → Успешно.
5. Журнал → Продажа #2 → Возврат 1 шт → поле «Банковская карта» = 75 → возврат создан; в журнале статус «Возвращён».
6. Возврат долга → Тест Клиент → 70 нал → остаток долга 100 отображается верно.
7. Выдача 20 «Аренда» → в смене «Всех выносов 20», «На текущий момент» уменьшилось.
8. Закрыть смену → пересчёт → Z-отчёт; цифры: продажи 345, получено 245 (нал 170 = 100 + 70 погашение, карта 75), возврат 75, долг выдан 170 / погашен 70.
9. Офлайн: отключить сеть → продать → «НЕПРОВЕДЁННЫЕ: 1», индикатор красный → включить → синхронизировано.
10. Горячие клавиши F, C, Enter, Esc работают во всех модалках.
