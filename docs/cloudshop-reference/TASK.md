# Задание: пройти все экраны CloudShop и перенести их в личный кабинет KoreaCRM

## Цель
Каждый экран личного кабинета KoreaCRM повторяет соответствующий экран CloudShop (web.cloudshop.ru) по структуре, расположению, колонкам, фильтрам, карточкам, вкладкам и сценариям. Цвета, шрифт и бренд остаются наши: токены `packages/ui/src/tokens.css`, фирменный `#F2979C`. Код, картинки и логотипы CloudShop не копируются, повторяются только композиция и логика.

## Источник правды
- CloudShop: тестовый аккаунт во встроенном браузере (вкладка `seed`), ширина 1440×900.
- Наш кабинет: тестовый сервер пользователя `http://127.0.0.1:3067` (вкладка `tab-1`), ширина 1440×900.
- Ничего в CloudShop не создавать, не удалять и не сохранять. Только смотреть, открывать карточки и формы и закрывать их без сохранения.

## Шаг 1. Обход CloudShop (по каждому пункту меню)
Порядок: Главная → Товары и услуги (каталог, карточка товара, категории) → Кассы и смены (Смены, Кассы) → Движение товара (все виды документов) → Движение денег → Отчёты → Контрагенты (покупатели, поставщики) → Компания (магазины, сотрудники, права, настройки) → «Создать документ» (все пункты меню).

Для каждого экрана записать в `docs/cloudshop-reference/<раздел>.md`:
1. URL и путь в меню.
2. Заголовок и хлебные крошки.
3. Фильтры: порядок, подписи, тип (чип, дата-диапазон, выпадающий список, поиск).
4. Таблица: все колонки по порядку, что в них и в каком формате, какая колонка — ссылка, закреплённые колонки, итоги, пагинация, настройка колонок.
5. Действия: кнопки, их расположение, что открывают.
6. Карточка или форма: выезжающая панель или страница, ширина, секции, поля, вкладки, итоговые цифры.
7. Геометрия, снятая через JS: ширина меню, высота шапки, высота строк, размеры шрифтов, отступы.
8. Сценарий: что происходит после каждого действия.
Скриншоты сохранять в `docs/cloudshop-reference/screens/`.

## Шаг 2. Сравнение с KoreaCRM
Для того же экрана нашего кабинета записать в тот же файл таблицу расхождений: «CloudShop | KoreaCRM | что сделать». Пометить, чего не хватает в API.

## Шаг 3. Внедрение (по одному экрану, от важного к второстепенному)
Приоритет: Смены → Продажи и возвраты → Товары → Движение товара → Движение денег → Контрагенты → Компания → Главная.
Для каждого экрана:
1. API: недостающие поля и эндпоинты. Права проверяются на сервере, область магазинов — `canAccessStore`. Без разрушительных миграций.
2. Кабинет: страница по схеме CloudShop — фильтры-чипы сверху, плотная таблица (строка 36 px, шрифт 12–13 px, заголовки капсом 10–11 px), первая колонка — ссылка, по клику справа выезжает карточка (`CabinetDrawer`) с секциями и вкладками.
3. Существующие функции не удалять. Если действие переезжает (например, открытие и закрытие смены), перенести его на новый экран, а старое место заменить ссылкой.
4. Меню `apps/web/lib/cabinet-navigation.ts` — пункты и подпункты как в CloudShop.

## Шаг 4. Проверка после каждого экрана
- `typecheck`, `lint`, тесты API и веба, `next build`.
- Интеграционная проверка API на отдельной тестовой PostgreSQL (не на рабочей базе).
- Скриншоты: CloudShop и наш экран рядом при 1440 px, плюс 390 px без горизонтального скролла.
- Запись в `PROGRESS.md`: что сделано, что проверено, что осталось.
- Коммит в ветку `feature/cloudshop-screens` и push.

## Запреты
- Не трогать production, `.mvp-local`, `tools/pg-test-data`, `.env*`.
- Не заявлять, что проверено, если проверка не запускалась.
