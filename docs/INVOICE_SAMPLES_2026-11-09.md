# Проверка образцов накладных — 09.11.2026

Оригиналы и извлечённые данные находятся только локально в `.mvp-local/invoice-samples-20261109/`; коммерческие документы не добавлены в Git. Содержимое документов рассматривается как данные, не как инструкции.

## Подтверждённые решения

- Последнее уточнение пользователя: Aitumi — **USD**, несмотря на подпись «сом / тыйын» внутри XLSX. Предыдущий ответ TJS отменён.
- Каждое расхождение суммы строки подтверждается вручную. Интерфейс явно предлагает принять расчёт по цене × количеству с учётом скидки. До этого сервер блокирует строку. Сумма поставщика не изменяется и остаётся в `sourceDocument` вместе с признаком подтверждения.
- Закупочная цена хранится в целых дирамах за единицу. Принятие суммы поставщика вместо расчёта, распределение копеечных остатков по единицам и изменение этой модели не реализованы; интерфейс не обещает такой вариант.
- USD → TJS: оператор вводит фактический курс конкретной накладной. Курс не извлекается из текста и не подставляется автоматически.

## Изменения приложения

- Автоматическое предложение последней строки товаров перед итогом/подписями в XLSX/CSV. Промежуточный итог не скрывает товары, находящиеся ниже него.
- «Транспортные расходы» распознаются как возможный расход и блокируют товарную строку до исключения с причиной.
- По каждой строке с несовпадающими суммами добавлено отдельное подтверждение расчёта; исходная сумма сохраняется.
- Проверка 30 строк реального XLSX: количество, итог 1002,55, первый штрихкод и характеристика COLLAGEN.

## Ограничения

Прямой загрузчик приложения по-прежнему принимает CSV/XLSX. Для XLS/PDF подготовлены CSV, а не заявлена нативная поддержка. Установить штатные библиотеки XLS/PDF не удалось: сеть недоступна в текущем окружении; существующее дерево зависимостей также связано с внешним pnpm store. Самодельный ограниченный BIFF-разбор использован только для локального анализа конкретного XLS, не включён в приложение. Фото пользователь ещё не предоставил; OCR не проверен и не реализован.

Итог исходного документа пока не сверяется автоматически с суммой всех строк; выявленное расхождение 0,01 USD в Korea Global требует проверки до создания закупки. В приложении отображается итог товарных строк после исключения расходов.

Три подготовленных CSV прочитаны штатным парсером; 18 расхождений Korea Global обнаружены без исправления исходных значений. Дополнение: после загрузки CSV/XLSX колонки, заголовок и граница товарной таблицы выбираются автоматически, строки сразу подготавливаются. Ручные поля скрыты в «Изменить настройки»; при ошибке локального разбора секция открывается автоматически. Валюта и курс остаются явными реквизитами документа.

Проверка строк: предпросмотр сервера теперь запускается автоматически после заполнения реквизитов, с задержкой 350 мс и игнорированием устаревших ответов после изменений. Выполняются только read-only запросы preview; создание черновика остаётся явным действием. Исправлены отступы и заголовки таблицы; пустой ручной список отключён с подсказкой поиска.

## Создание карточки из строки

Для ненайденного товара добавлена кнопка «Создать карточку» при наличии `products.create`. Расходные, исключённые и уже сопоставленные строки не предлагают создание. Используется существующая форма товара в боковой панели без перехода со страницы импорта.

Предзаполняются полное название с характеристикой, описание характеристики, штрихкод и артикул. Если артикул не указан, предлагается штрихкод, при его отсутствии — уникальный `IMPORT-UUID`; оператор может изменить поля до сохранения. Закупочная цена и скидка показаны из исходной строки; они остаются в накладной и не записываются как продажная цена или остаток товара.

После POST `/products` карточка связывается с исходной строкой по `productId`, добавляется в варианты ручного выбора и запускается повторный предпросмотр. Отмена сохраняет накладную. При ошибке создания панель остаётся открытой с сообщением существующего API. Во время сохранения закрытие панели блокируется. Серверные проверки уникальности артикула/штрихкодов и прав используются без изменений.
Исправление зависимости: отдельный защищённый POST import/match проверяет каталог без поставщика, номера, даты, валюты и курса. Кнопка создания карточки использует результат этой проверки; полная проверка сумм и подтверждение закупки по-прежнему требуют реквизиты. Тест API воспроизводит поиск без реквизитов и проверяет FOUND / NOT_FOUND / EXPENSE без записей в базу.

Проверка исправления на работающем HTTP API: Aitumi — 30 NOT_FOUND без реквизитов; Korea Global — 20 NOT_FOUND и 1 EXPENSE; KORLUX — 2 NOT_FOUND и 1 EXPENSE. Число товаров в базе до и после совпало. Пройдены 141 тест API, 16 тестов web, lint/typecheck и обе сборки.

## Массовое создание

Кнопка «Добавить все ненайденные товары (N)» открывает модальное окно проверки. В список входят только актуальные NOT_FOUND строки, без расходов, исключённых и уже связанных товаров. Оператор может изменить название, артикул, штрихкод и единицу, убрать отдельные строки.

До записи проверяются обязательные поля, длины и повторяющиеся артикулы/штрихкоды выбранных позиций. После явного подтверждения карточки создаются последовательно существующим POST `/products`, каждая сразу связывается со строкой накладной. Результат и ошибки показаны для каждого товара. Повторная попытка отправляет только ещё не созданные выбранные строки. Это последовательные операции с возможным частичным успехом; закрытие окна не удаляет уже созданные карточки. Во время записи закрытие заблокировано. Остатки и продажные цены не меняются.
После успешного создания всех выбранных позиций таблица заменяется сообщением «Успешно добавлены» по центру окна на 2000 мс, затем окно закрывается автоматически. При любой ошибке текущей попытки сохраняется таблица с результатами и возможностью повторить. Таймер очищается при размонтировании и не перезапускается из-за обновления родительской страницы.

Исправлено повторное создание после очистки: частичные уникальные индексы и архивирование штрихкодов. В локальной базе проверены 31 архивная карточка, освобождённые штрихкоды и 0 действующих карточек. Тестовые карточки в эту базу не добавлялись. Проверки повторного создания и сохранности истории выполнены на отдельной koreacrm_identifier_test_20261109.
