# Магазины, роли и журнал действий

## Магазины

В личном кабинете откройте **Управление → Магазины**. Пользователь с правом `stores.view` видит только назначенные ему магазины. Пользователь с `stores.create` и доступом ко всей сети может создать магазин. Карточка содержит название, постоянный код, адрес, телефон, ответственного, команду, кассовые устройства и сводку продаж за 30 дней.

Права `stores.edit` и `stores.archive` разделены. Приостановка и архивирование блокируются, пока есть открытая кассовая смена. Неактивный магазин больше не предлагается при входе в кассу и не принимает новые продажи. Исторические данные остаются в БД. Назначать сотрудников из карточки может пользователь с `employees.edit`, если у него есть доступ к магазину и права сотрудника не превышают его собственные.

У сотрудника можно выбрать **основной магазин**. Касса выбирает его после входа. Незавершённая локальная продажа имеет приоритет, чтобы её можно было отправить в тот же магазин. Основной магазин должен быть активным и доступным сотруднику.

## Роли

На экране **Сотрудники и роли → Роли и права** можно создавать собственные роли и изменять название и разрешения существующих ролей, в том числе системных. Код роли остаётся постоянным. Системную роль нельзя удалить. Роль `SUPERUSER` защищена от изменения и назначается только действующим суперпользователем. Нельзя отключить или удалить последнего активного суперпользователя.

Изменения прав записываются в `AuditLog`. После изменения роли seed сохраняет её права: поле `Role.permissionsCustomizedAt` не даёт seed восстановить исходные разрешения. Новые разрешения в будущем нужно назначать изменённым ролям вручную. Первичная учётная запись из seed переводится с `OWNER` на `SUPERUSER` при обновлении; пароль при этом не меняется.

## Журнал

Экран **Аналитика → Журнал действий** и `GET /audit` доступны только роли `SUPERUSER`. Журнал показывает автора, время, действие, объект, значения до и после; есть поиск, даты и страницы. Доступ проверяет API, скрытие пункта меню служит только удобству интерфейса.

## Обновление VPS

Перед запуском новой версии примените миграцию `20261027010000_store_profiles` через `prisma migrate deploy`, затем запустите seed и обновите API и кабинет. Проверьте создание тестового магазина, назначение сотрудника, выбор основного магазина в кассе, редактирование роли и доступ к журналу. Для рабочей БД не используйте `migrate dev`.
