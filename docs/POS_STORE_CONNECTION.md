# Код точки и доступ сотрудников в POS 0.2.6

## Первая настройка

У каждой точки уже есть уникальный постоянный `Store.code`. В ЛК откройте **Магазины → нужная точка → Код подключения кассы** и скопируйте его.

При первом запуске новой версии POS введите адрес сервера и этот ID-код. Касса проверит активность точки и запомнит её на устройстве отдельно для каждого адреса сервера. Далее показываются название магазина и обычный вход сотрудника по паролю либо QR/штрихкоду. Выход сотрудника и перезапуск программы не сбрасывают точку.

Код точки — идентификатор для настройки, а не пароль. Без личного входа сотрудника он не даёт доступ к данным или продажам. Код точки и код кассира различаются.

## Назначение сотрудников

В кассы точки могут входить сотрудники, назначенные в её команду и имеющие право `sales.create`. Сохраняется существующий явный доступ «ко всей сети»: такие пользователи допускаются в любую активную точку. Даже их POS-сессия ограничивается магазином конкретной кассы.

Чтобы перевести сотрудника, добавьте его в команду нового магазина, затем снимите со старого. В другой магазин он входит через кассу, настроенную на код новой точки. Удаление назначения проверяется сервером при следующем запросе и обновлении токена. Проверка одинакова для пароля и карточки кассира.

Уже зарегистрированная касса не перепривязывается простым вводом другого кода. Администратор должен сначала закрыть её смену, убедиться в отправке чеков и отвязать устройство в ЛК; затем в программе выбрать **Изменить точку**. Локальные чеки и каталоги при настройке не удаляются.

## Без связи

Первую настройку и первый вход выполняют при доступном сервере. Сохранённый офлайн-вход допускается только для магазина, на который настроена касса. При полученном от сервера отказе доступа совпавшие локальные учётные данные удаляются; очередь продаж остаётся.

Сохраняется существующее ограничение офлайн-авторизации: ранее подтверждённые данные доступны до 7 дней. Пока устройство полностью без связи, оно не может узнать о новом снятии сотрудника с магазина. Мгновенный отзыв требует связи; нельзя считать офлайн-проверку текущим состоянием команды на сервере.

## Обновление

Сначала обновите API и ЛК, затем установите POS 0.2.6. Новая миграция не нужна: используются существующие `Store.code`, `UserStore` и `PosDevice`.

Старые зарегистрированные POS продолжают получать серверную проверку назначения при входе. Первичная регистрация нового POS теперь требует кода точки, поэтому для нового устройства нужна новая версия программы. После обновления приложения код точки вводится один раз, даже если ранее магазин выбирался автоматически.

## Проверки

- Регрессионные тесты: правильный/неизвестный код, сотрудник чужой точки, QR, запрет смены привязки, удаление назначения, refresh, отключённая касса, ограничение сетевого пользователя одной точкой.
- `tools/verify-pos-store-connection.mjs` выполняет HTTP-проверки с настоящей PostgreSQL и создаёт тестовые записи. Он принимает только локальную БД с `_pos_store_test` в имени; на рабочей БД его запускать нельзя.
- Локальный MVP и production не используются как хранилище данных этого сквозного теста.
